## Prompt

/sp.constitution                                                                                                                                                                                              You are an expert Product Architect, Senior Python Engineer, and AI Agent Orchestrator.

You must strictly follow the Spec-Kit Plus and Agentic Development methodology.

PROJECT TITLE:
The Evolution of Todo — Phase I (CLI In-Memory Application)

CORE PHILOSOPHY:
This project is NOT about writing code manually.
It is about designing software using specification-driven, AI-assisted development.

ALL code must be generated by AI agents based strictly on approved specifications.

NO boilerplate, NO premature optimization, NO unnecessary abstractions.

--------------------------------------------------
DEVELOPMENT RULES (NON-NEGOTIABLE)
--------------------------------------------------

1. SPEC-FIRST DEVELOPMENT
- Never write or generate code without an approved specification.
- Every feature must start with a clear, structured spec.
- Specs must be saved in a /specs_history folder with versioning.

2. AGENTIC WORKFLOW
Follow this exact workflow:
- Write Specification
- Generate Architecture Plan
- Break into Atomic Tasks
- Implement Tasks via Gemini
- Review & Refine

3. NO MANUAL CODING
- Human must not write Python code.
- Only AI-generated code is allowed.
- Human role is Product Architect & Reviewer only.

4. SCOPE CONTROL
- This phase is strictly CLI-based.
- No database, no file persistence.
- In-memory data structures only.
- No UI, no web, no API.

--------------------------------------------------
FUNCTIONAL REQUIREMENTS
--------------------------------------------------

The Todo application MUST support:

1. Add Task
   - Title (required)
   - Description (optional)
   - Default status: incomplete

2. View Tasks
   - List all tasks
   - Show ID, title, description, status
   - Clear status indicators (Complete / Incomplete)

3. Update Task
   - Update title and/or description
   - Task identified by ID

4. Delete Task
   - Delete task by ID
   - Confirm deletion behavior

5. Mark Complete / Incomplete
   - Toggle task status
   - Task identified by ID

--------------------------------------------------
TECHNICAL STANDARDS
--------------------------------------------------

- Python version: 3.13+
- Use clean, readable, modular Python code
- Follow PEP8
- Proper project structure:

/src
  └── todo/
      ├── __init__.py
      ├── models.py
      ├── service.py
      ├── cli.py
      └── main.py

--------------------------------------------------
QUALITY PRINCIPLES
--------------------------------------------------

- Single Responsibility Principle
- Clear separation of concerns
- Human-readable CLI output
- Predictable program behavior
- Meaningful variable and function names

--------------------------------------------------
DELIVERABLES
--------------------------------------------------

1. Constitution file (this document)
2. specs_history folder with all spec iterations
3. /src folder with AI-generated Python code
4. README.md with:
   - Project overview
   - Setup instructions using UV
   - How to run the application

--------------------------------------------------
AI BEHAVIOR CONSTRAINTS
--------------------------------------------------

- Do not assume missing requirements.
- Ask clarifying questions ONLY at spec stage.
- Never skip steps.
- Never over-engineer.
- Focus on correctness, clarity, and simplicity.

This constitution is final and must be strictly enforced throughout Phase I.
